# MG Auto Studio

**扁平矢量 MG 动画（Motion Graphics）全流程生产手册** ｜ Claude Code Skill ｜ v1.0

从「一句需求」到「一条过审的成片」的完整流水线 —— 但它真正解决的问题**不是"画得好"，是"全片一致"**。
几十个镜头、几十张参考帧、若干标签/图标/UI，必须像同一个人一次做完的。
本手册的每一步都在为「一致性」服务。

> 这不是一份"提示词大全"，是一份**用真金白银烧出来的操作规程** ——
> 每条铁律背后都写着它是哪天、在哪个镜头上、亏了多少积分换来的。

## 它解决什么问题

AI 生成 MG 动画的难点从来不是单张图好看，而是**跨镜头的连续性**：

| 症状 | 根因 | 手册对应章节 |
|------|------|--------------|
| 每个镜头主角换脸 | 形象只用文字描述、没用图传 | §1 收资料 · 必给主人公形象 |
| 全片风格飘 | 没有全局风格提示词 | §2 视觉模型拆风格 |
| 版图/标签被模型重画走形 | 已定稿的东西在提示词里又描述了一遍 | §7 已定稿的要"闭嘴"，改成 @ 图 |
| 拼接处有色差、断层 | 按场景切了太多块 | §9.8 生V1 · 能合并的必须合并 |
| 改一个 bug，带出三个新 bug | 没有"问题清单"，改到第 5 轮还在问用户 | §0.5 核验五问 + 帧问题清单 |
| 交付了才发现版图被切出两条缝 | 收口时没有人肉眼逐块看图 | 关卡 I（`tools/收口.py`） |

## 全流程一页速查

```
第0步 收资料 ──────────── 需求 / 主人公形象 / 音色 / 风格参考图（+ 追问 6 项）
  ↓
第1步 视觉模型拆风格 ──── 全局风格提示词 → 写进脚本 & 每条提示词
  ↓
第2步 初稿 ───────────── 文件A(纯文案) + 文件B(序号|台词|简述)  → 用户定稿
  ↓
第3步 细化 ───────────── 七列版（⑤图片提示词逐格完整，绝不写"同上"）
  ↓
第4步 生成参考帧 ─────── 扫全整个镜头，挑「元素最全」的那帧当底稿
                          + 连续性驱动 + 定款先行 + 重点元素单独拆出
         ↑                    ↓
         └── 回改脚本 ←── 用户检查布局/元素 ──┐
             （改动必须落回脚本源头）         │  不通过就循环
  ↓                                           │
第5步 文字校验与修复 ──────────────────────────┘
  ↓
第6步 按场景切块 ─────── 文件C（三种模式 A/B/C，默认 A = 元素锚定）
                         🔴 能合并的镜头必须合并，块越少越好
  ↓
🔴 生视频前核验 ──────── 三查：同版本 / 同风格 / 图没改错 → 不过不许往下
  ↓
🔴 生视频前先问用户 ──── 报清楚：几块 × 几秒 × 多少积分 × 当前余额，等点头
  ↓
第7步 生成视频 ───────── 逐块生成（每块最多 3 次）→ 按帧号拼接 → 关卡 J 验收
```

**贯穿始终**：每步产出 → 用户确认 → 下一步；**积分先报**；文件归位当日 `MMDD/` 目录。

## 七条铁律

手册开头只有 7 条，**一眼扫完** —— 读不完的规矩等于没有规矩。

1. **报积分 → 用户点头 → 才动手。**
2. **改图走入口：先跑 `tools/改图.py`，改完比对原图。**
3. **打回重做只走「帧改帧 + 局部重生成」。** 参考物只认两种：成片里的某一帧、成片里出现过的元素图。**绝对不许新画一张风格不一致的示意图。**
4. **每条「不许 X / 必须 Y」都要有出处；每张成品都要跟定稿对。** 判据自己编的 → 核验再认真也是自证。
5. **截帧即定「帧问题清单」；清单没销完，不许定稿，也不许回头问用户。** 目标是全自动，中间不用问用户。
6. **定底稿前，先把整个镜头扫一遍，取「元素最全」的那一帧。** 起点不全，改出来的也不可能全。
7. **成品只能由 `tools/收口.py` 写出来 —— 没跑完自检，成品文件根本不存在。**

> 规矩写了两处、还引了用户原话，一样没用 —— **所以这里把规矩做成了关卡：不是提醒你，是让你跑不起来。**

## 四道关卡工具

`tools/` 下五个脚本，核心设计思想是同一句：**「写下来」挡不住「没读」，所以把规矩做成跑不起来的关卡。**

| 工具 | 是什么 | 它凭什么拦得住 |
|------|--------|----------------|
| **`取帧.py`** | 定底稿前的取帧器 | 主产出是**接片图**，强制人眼定帧（自动打分实测不可靠） |
| **`改图.py`** | 改图的**唯一入口** | 关卡 A/B：每个画面元素必须声明「本版」；声明要"换"的必须给出定稿图路径且**文件真存在**。缺一样直接跑不起来 |
| **`比对.py`** | 改图后 / 生视频前的核验 | 量化"只有该改的地方变了"——判据取自底稿自己相邻帧的抖动基线，比它大一个量级就是被重画了 |
| **`收口.py`** | **成品唯一入口**（关卡 I） | ① 通用两查：**越界**（变了但不在掩码里）+ **漏改**（在掩码里却没变）；② 强制逐块看图，每格必须写一句"这一格里有什么"；③ 逐条销项。**它不点头，成品文件一个字节都不会被写出来** |
| **`验收视频.py`** | **成片拼接唯一入口**（关卡 J） | 四查，其中「切点闭环」要求台账里每段写出源起止帧与成片绝对入帧，脚本自己算连续性；「切出来真对」会真去切、数帧数，一帧不多一帧不少 |

**共用约定**：所有脚本默认 **dry-run（只打印不提交）**，看清楚了再加 `--go` / `--成品` 真跑。
校验不通过时退出码为 1，且**不花积分**。

## 参考帧修订循环（本流程的骨架）

```
        ┌─────────────────────────────────────────────┐
        │                                             │
  生成参考帧 ──→ 用户检查布局/元素 ──→ 不通过 ──→ 回改脚本源头
        │                                             │
        └──→ 通过 ──→ 文字校验与修复 ──→ 切块 ──→ 生视频
```

三个最容易断掉的环节：

- **改动必须落回脚本源头。** 只改这一次的图 = 下次照样错。
- **改 bug 的提示词必须重写，不许复用原提示词。** 复用 = 把产生 bug 的语境再喂一遍。
- **禁止整块重跑**，只重生成「有问题的镜头区间」。

## 生视频三条约规

| 条规 | 内容 | 例外 |
|------|------|------|
| **默认工具** | 即梦 CLI（`dreamina`） | 用户另行指定别的工具 |
| **默认分辨率** | **一律 720p**（必须显式写 `--video_resolution 720p`） | 720p 生成不了，或用户给了别的标准 |
| **生视频前** | **必须先问用户**，报告「几块 × 几秒 × 多少积分 × 当前余额」，等点头才提交 | 用户任务开头就声明免审 |

> **为什么「先问」要写死**：有一次没问，拿项目里的图当探针烧掉 **2520 积分**（余额 2642 → 122）。
> 「积分随便用」那句话的授权语境是**做片子**，不是**做实验**。

同理，**不许自作主张升 1080p** —— 实测贵 **3.2 倍**。

## 环境依赖

**Python 3**（脚本层）

```bash
pip install pillow opencv-python numpy
```

**外部工具**

| 用途 | 依赖 |
|------|------|
| 图生视频 / 文生视频 | 即梦 CLI（`dreamina`，装在 `~/.local/bin/`） |
| 风格拆解（视觉模型） | 视觉理解模型（如 Qwen-VL），把风格参考图拆成全局风格提示词 |
| 字体（取帧/验收出图） | macOS 系统字体 `STHeiti` / `Songti`（脚本内置候选路径） |

> 判定常量（抖动基线 / 画幅 / 背景区采样框）**每个项目必须自己测一遍，不许照抄** ——
> 照抄会让三查给出一个"看起来正常、其实毫无意义"的数字。
